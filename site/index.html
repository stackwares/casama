Capabilities

Not a chat window. A colleague with a desk.

Most AI tools trap a smart model inside a text box. Casama gives every bot a real computer, long-term memory, a schedule, and guardrails you control.

01 · Isolated Computers & Desktop Companion

A real computer for every bot—or lend a folder on yours

Each bot gets a sandboxed Linux computer with a shell, files, code tools, and a Chromium browser. Watch the screen live, take over mouse and keyboard whenever a site needs a human, or let the computer sleep automatically when idle. Want a bot to work on local files? Pair the Desktop Companion and grant access only to the folders you pick.

Sandboxed Cloud / Docker Computer gVisor

Read-only root, zero Linux capabilities, non-root user, egress proxy blocking private IPs, and automatic snapshots before risky shell commands.

Your Mac, Windows, or Linux Companion

Run local stdio MCP servers, hand coding tasks to Claude Code, Codex, or Cursor on your machine, and attach the front window with a global hotkey.

02 · Autonomy, Approvals & Spend Caps

Asks before it acts

Set autonomy per bot and per action rule: allow, allow within limits, ask first, or hand off. Before a high-risk command runs, Casama snapshots the computer so you can roll back in one click.

03 · Memory, Knowledge & Skills

Remembers across chats and learns by watching

Bots recall facts, preferences, and past runs across every conversation—with a personal profile ("About you") that never leaks into team spaces unless you share it. Upload PDFs, Drive folders, or Notion pages for cited answers, or record a task once on the bot's computer to turn it into a reusable SKILL.md.

fact Stack uses Postgres 17 + RLS pref Concise diffs, no fluff skill /weekly-release-notes cited SOC2-Policy.pdf (p. 12)
04 · Routines, Watchers & Projects

Works while you're away

Schedule routines on a cron timer, trigger them from webhooks, emails, or calendar events, or set a "Tell me when" watcher that checks a page or query at zero model tokens until something changes. For multi-day goals, create a Project with milestones and a budget—the lead bot works in sessions until it's done.

System Architecture

Engineered like infrastructure, not a weekend wrapper.

Every boundary in Casama—from database rows to container syscalls and outbound network packets—is isolated and verified in CI.

Layer 1 · Surfaces

Apps, Channels & MCP

Native Flutter apps on 6 platforms, web app, CLI, voice calls, chat bridges (Telegram, Slack, WhatsApp, Email), and remote HTTP / stdio MCP clients.

Passkeys + 2FA SSE Stream @casama/mcp
Layer 2 · Control Plane

API Server & DBOS Durable Worker

Fastify OpenAPI control plane paired with DBOS durable workflows. Model calls, tool executions, approvals, and budget checks are persisted step by step.

DBOS Workflows Model Router OpenTelemetry
Layer 3 · Isolation Boundary

Postgres RLS + Sandboxed Computers

Every table enforces Postgres Row-Level Security. Bot computers run behind a sandbox supervisor and egress proxy that injects secrets and blocks private networks.

Postgres RLS gVisor / Docker Egress Proxy

Row-Level Security everywhere

Every workspace table has a mandatory Postgres RLS policy and an automated cross-tenant test proving Workspace A can never read Workspace B.

Hardened Linux sandboxes

Computers run non-root with a read-only root filesystem, dropped Linux capabilities, PID/memory limits, and gVisor (runsc) on Linux hosts.

Zero-leak secret proxy

API keys and 1Password/Bitwarden credentials are substituted at the network boundary for allowed domains only—never visible to the LLM.

Encryption & full ownership

Optional encryption at rest before Postgres (local key or AWS KMS), configurable retention windows, and one-click full workspace ZIP export.
